# E2E Testing with Playwright

End-to-end tests verify the plugin inside a real Logseq Electron application using [Playwright](https://playwright.dev/).

## Architecture Overview

```
npm run test:e2e:auto
        │
        ▼
scripts/run-e2e.ts            # Orchestrator
  ├─ scripts/setup-logseq.ts  # Resolves/downloads Logseq binary
  │    └─ logseq/ensure-logseq.ts   # Download, cache & extract logic
  └─ npm run test:e2e          # Runs Playwright
        └─ playwright.config.ts
              ├─ globalSetup  → tests/e2e/global-setup.ts
              └─ testDir      → tests/e2e/*.spec.ts
```

### Key Components

| File | Purpose |
|------|---------|
| `playwright.config.ts` | Playwright config (test dir, retries, tracing) |
| `tests/e2e/global-setup.ts` | Creates temp dirs (`.tmp/`), writes `runtime.json` |
| `tests/e2e/*.spec.ts` | Test specs that launch Logseq via Electron |
| `scripts/run-e2e.ts` | Orchestrator: runs setup → sets `LOGSEQ_EXECUTABLE` → runs tests |
| `scripts/setup-logseq.ts` | CLI wrapper for `ensure-logseq.ts` |
| `scripts/logseq/ensure-logseq.ts` | Downloads & caches Logseq binary per `logseq-versions.json` |

### How Tests Launch Logseq

Tests use `@playwright/test`'s `_electron` API to launch Logseq as an Electron app:

```ts
import { _electron as electron } from "@playwright/test";

const app = await electron.launch({
  executablePath: runtime.executablePath,
  args: [runtime.graphDir],
  env: { ...process.env, HOME: runtime.homeDir, XDG_CONFIG_HOME: runtime.xdgDir },
});
const window = await app.firstWindow();
```

The `runtime.json` file (generated by global setup) provides `executablePath`, `graphDir`, `homeDir`, and `xdgDir`.

## NPM Scripts

| Script | Command | Description |
|--------|---------|-------------|
| `test:e2e` | `playwright test` | Run tests headless (requires `LOGSEQ_EXECUTABLE` env var) |
| `test:e2e:auto` | `tsx scripts/run-e2e.ts` | Full automated run: setup Logseq binary + run tests |
| `test:e2e:ui` | `playwright test --ui` | Interactive UI mode with time-travel debugging |
| `test:e2e:debug` | `PWDEBUG=1 playwright test` | Step-through debugger with Playwright Inspector |

### Running Tests

**Fully automated** (downloads Logseq if needed):

```bash
npm run test:e2e:auto
```

**Manual** (when `LOGSEQ_EXECUTABLE` is already set):

```bash
export LOGSEQ_EXECUTABLE=/path/to/logseq
npm run test:e2e
```

## Visual / Interactive Modes

### UI Mode (`test:e2e:ui`)

Opens Playwright's interactive test runner with:
- A sidebar to select/filter tests
- Live browser view while tests run
- **Time-travel debugging**: click any action in the timeline to see the DOM snapshot at that point
- Watch mode: re-runs on file changes

```bash
npm run test:e2e:ui
```

> **Note:** Requires `LOGSEQ_EXECUTABLE` to be set. If you haven't run `test:e2e:auto` before, run setup first:
> ```bash
> export LOGSEQ_EXECUTABLE=$(npx tsx scripts/setup-logseq.ts legacy | jq -r .executablePath)
> npm run test:e2e:ui
> ```

### Debug Mode (`test:e2e:debug`)

Opens the **Playwright Inspector** — a step-by-step debugger:
- Pause/resume execution at each action
- Inspect DOM elements with the locator picker
- View console logs in real time

```bash
npm run test:e2e:debug
```

### Headed Mode (ad-hoc)

Run tests with the browser window visible but without pausing:

```bash
npx playwright test --headed
```

### Trace Viewer (post-mortem)

Traces are recorded on first retry (configured via `trace: "on-first-retry"` in `playwright.config.ts`). View them with:

```bash
npx playwright show-trace test-results/*/trace.zip
```

The trace viewer shows:
- Timeline of actions with DOM snapshots
- Network requests
- Console logs
- Source code mapping

## Configuration

### `playwright.config.ts`

```ts
export default defineConfig({
  testDir: "./tests/e2e",
  globalSetup: "./tests/e2e/global-setup.ts",
  reporter: process.env.CI ? "blob" : "html",
  retries: process.env.CI ? 2 : 0,
  workers: 1,
  timeout: 60_000,
  use: {
    trace: "on-first-retry",
  },
});
```

| Option | Value | Notes |
|--------|-------|-------|
| `testDir` | `./tests/e2e` | All `*.spec.ts` files live here |
| `globalSetup` | `global-setup.ts` | Prepares `.tmp/` dirs and `runtime.json` |
| `reporter` | `html` / `blob` | HTML locally, blob for CI merging |
| `retries` | `0` / `2` | No retries locally, 2 in CI |
| `workers` | `1` | Sequential — Electron tests share a single app |
| `timeout` | `60s` | Per-test timeout |
| `trace` | `on-first-retry` | Records trace only on first retry |

### Logseq Binary Management

The Logseq binary version is pinned in `logseq-versions.json`. The setup script:

1. Reads the config for the requested channel (`legacy` or `db`)
2. Detects the current platform/arch
3. Downloads the matching release from GitHub (if not cached)
4. Extracts and caches it in `.cache/logseq/<channel>/<tag>/<platform-arch>/`
5. Outputs `{ executablePath, ... }` as JSON

## Writing New Tests

### File Location

Place test files in `tests/e2e/` with the `.spec.ts` extension.

### Template

```ts
import fs from "node:fs";
import path from "node:path";
import { test, expect, _electron as electron } from "@playwright/test";

function loadRuntimeConfig() {
  const runtimePath = path.resolve(".tmp/runtime.json");
  if (!fs.existsSync(runtimePath)) {
    throw new Error(`Runtime config not found at ${runtimePath}.`);
  }
  return JSON.parse(fs.readFileSync(runtimePath, "utf8"));
}

test("my feature test", async () => {
  const runtime = loadRuntimeConfig();

  const app = await electron.launch({
    executablePath: runtime.executablePath,
    args: [runtime.graphDir],
    env: {
      ...process.env,
      HOME: runtime.homeDir,
      XDG_CONFIG_HOME: runtime.xdgDir,
    },
  });

  try {
    const window = await app.firstWindow();
    await window.waitForLoadState("domcontentloaded");

    // Your test assertions here
    await expect(window.locator("body")).toBeVisible();
  } finally {
    await app.close();
  }
});
```

### Best Practices

- **Always close the app** in a `finally` block to avoid zombie processes
- **Use `loadRuntimeConfig()`** to get paths — don't hardcode them
- **Keep tests independent** — each test should set up its own state
- **Use meaningful test names** that describe the user-visible behavior
- **Leverage Playwright locators** (`getByRole`, `getByText`, `locator`) over raw CSS selectors

## CI Integration

- **Reporter**: Uses `blob` reporter in CI for parallel shard merging
- **Retries**: 2 retries in CI to handle flaky Electron startup
- **Traces**: Automatically recorded on first retry — upload `test-results/` as CI artifact for debugging

### Artifacts to preserve in CI

```
playwright-report/    # HTML report
test-results/         # Traces and screenshots
```

Both directories are `.gitignore`'d.

## Troubleshooting

| Problem | Solution |
|---------|----------|
| `LOGSEQ_EXECUTABLE is not set` | Run `npm run test:e2e:auto` or export the var manually |
| `Runtime config not found` | Global setup failed — check `.tmp/runtime.json` exists |
| Tests hang on Electron launch | Increase `timeout` in config; ensure no other Logseq instance is running |
| `test:e2e:ui` shows no tests | Make sure specs are in `tests/e2e/` and end with `.spec.ts` |
| Trace not recorded | Traces are only captured on first retry; set `trace: "on"` temporarily to always record |
